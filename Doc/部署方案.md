# Worktime Server 后端部署方案

> 适用项目：Worktime 打卡应用后端（Dart + Shelf + SQLite）
> 最后更新：2026-05-10

---

## 1. 概述

Worktime Server 是一个轻量级后端服务，基于 Dart Shelf 框架，使用 SQLite 作为数据库。本文档详细说明将其部署到生产服务器的完整流程。

### 技术栈

| 组件 | 技术 | 说明 |
|------|------|------|
| 语言 | Dart 3.0+ | 编译为原生二进制，无需运行时依赖 |
| HTTP 框架 | Shelf | 轻量级请求/响应处理 |
| 数据库 | SQLite | 单文件数据库，无需独立数据库服务 |
| 认证 | JWT + bcrypt | 无状态 Token 认证 |
| 部署形态 | Docker / 原生二进制 | 可编译为单一可执行文件 |

### 架构特点

- **离线优先**：客户端本地 SQLite 为主数据源，服务端负责同步备份
- **增量同步**：通过 `updatedAt` 时间戳实现
- **幂等同步**：基于 `clientId`（客户端自增 ID）去重

## 2. 部署方式

### 2.1 Docker 部署（推荐）

#### 前置条件

- 目标服务器已安装 Docker（≥ 20.x）和 Docker Compose（可选）

#### 构建镜像

```bash
cd /home/admin/My_Prj/work_attendance/worktime_server

# 构建 Docker 镜像
docker build -t worktime-server:latest .

# 查看镜像
docker images | grep worktime-server
```

#### 运行容器

```bash
# 基本运行
docker run -d \
  --name worktime-server \
  -p 8080:8080 \
  -v /data/worktime/data:/app/data \
  -e JWT_SECRET="your-strong-secret-key" \
  -e ALLOWED_ORIGIN="https://youruser.github.io" \
  --restart unless-stopped \
  worktime-server:latest
```

参数说明：

| 参数 | 说明 |
|------|------|
| `-d` | 后台运行 |
| `-p 8080:8080` | 映射宿主机 8080 端口到容器 |
| `-v /data/worktime/data:/app/data` | 持久化数据库文件到宿主机 |
| `-e JWT_SECRET` | 设置 JWT 签名密钥（**必须修改**） |
| `-e ALLOWED_ORIGIN` | 设置前端域名，用于 CORS 限制 |
| `--restart unless-stopped` | 容器退出时自动重启（手动停止除外） |

#### 使用 Docker Compose（推荐）

创建 `docker-compose.yml`：

```yaml
version: '3.8'

services:
  server:
    image: worktime-server:latest
    container_name: worktime-server
    ports:
      - "127.0.0.1:8080:8080"
    volumes:
      - /data/worktime/data:/app/data
    environment:
      - PORT=8080
      - DB_PATH=data/data.db
      - JWT_SECRET=${JWT_SECRET:?err}
      - ALLOWED_ORIGIN=https://youruser.github.io
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8080/api/health"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 10s
```

对应的 `.env` 文件（与 compose 同目录）：

```bash
JWT_SECRET=your-strong-secret-key-here
```

启动：

```bash
docker compose up -d
docker compose logs -f
```

### 2.2 原生二进制部署（更高性能）

Dart 可编译为原生机器码，生成的单一可执行文件无需任何运行时依赖。

#### 编译

```bash
cd /home/admin/My_Prj/work_attendance/worktime_server

# 编译为原生二进制
dart compile exe bin/server.dart -o worktime-server

# 查看文件大小
ls -lh worktime-server
# 约 8-12 MB（取决于 Dart SDK 版本）
```

#### 部署到服务器

```bash
# 将二进制文件和 .env 上传到服务器
scp worktime-server .env your-server:/opt/worktime/

# 或者使用 rsync
rsync -avz worktime-server .env user@your-server:/opt/worktime/
```

#### 创建 systemd 服务（生产环境）

`/etc/systemd/system/worktime-server.service`：

```ini
[Unit]
description=Worktime Server
after=network.target

[Service]
type=simple
user=worktime
group=worktime
WorkingDirectory=/opt/worktime
ExecStart=/opt/worktime/worktime-server
Restart=always
RestartSec=5
EnvironmentFile=/opt/worktime/.env

# 安全加固
NoNewPrivileges=true
ProtectHome=true
ProtectSystem=strict
ReadWritePaths=/opt/worktime/data
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

创建用户并启动：

```bash
# 创建专用用户
sudo useradd -r -s /bin/false worktime

# 创建目录并设置权限
sudo mkdir -p /opt/worktime/data
sudo chown -R worktime:worktime /opt/worktime

# 放置二进制和配置
sudo cp worktime-server /opt/worktime/
sudo cp .env /opt/worktime/

# 启动服务
sudo systemctl daemon-reload
sudo systemctl enable worktime-server
sudo systemctl start worktime-server
sudo systemctl status worktime-server
```

常用管理命令：

```bash
sudo systemctl status worktime-server      # 查看状态
sudo systemctl restart worktime-server     # 重启
sudo journalctl -u worktime-server -f      # 查看实时日志
sudo journalctl -u worktime-server --since "1 hour ago"  # 查看最近 1 小时日志
```

## 3. 环境配置

### 3.1 环境变量说明

| 变量 | 默认值 | 必填 | 说明 |
|------|--------|------|------|
| `PORT` | `8080` | 否 | 监听端口 |
| `DB_PATH` | `data.db` | 否 | SQLite 数据库文件路径 |
| `JWT_SECRET` | `change-me-in-production` | **是** | JWT 签名密钥，生产环境必须修改 |
| `ALLOWED_ORIGIN` | `*` | **推荐** | 允许的跨域来源，建议指定具体域名 |

### 3.2 生产环境 `.env` 示例

```bash
PORT=8080
DB_PATH=data/data.db
JWT_SECRET="$(openssl rand -base64 32)"   # 生成 32 字节随机密钥
ALLOWED_ORIGIN=https://youruser.github.io
```

生成 JWT 密钥：

```bash
# 方法 1：使用 openssl
openssl rand -base64 32

# 方法 2：使用 uuidgen
uuidgen | sha256sum | head -c 64
```

### 3.3 ALLOWED_ORIGIN 配置说明

`ALLOWED_ORIGIN` 控制 CORS 头 `Access-Control-Allow-Origin`：

- `*` — 允许所有来源（开发环境）。**生产环境不建议使用**
- `https://youruser.github.io` — 只允许 GitHub Pages 域名访问
- `https://youruser.github.io,https://custom-domain.com` — 注意：当前服务器实现只支持单一来源，如需多来源需修改代码

## 4. 反向代理 + SSL（生产必需）

建议在前方加 Nginx/Caddy 处理 SSL 终止和反向代理，不要让 Shelf 直接暴露给公网。

### 4.1 Nginx 配置

```nginx
# /etc/nginx/sites-available/worktime

server {
    listen 80;
    server_name your-domain.com;

    # HTTP → HTTPS 重定向（如果配置了 SSL）
    location / {
        return 301 https://$host$request_uri;
    }
}

server {
    listen 443 ssl http2;
    server_name your-domain.com;

    # SSL 证书（推荐使用 acme.sh 或 Certbot）
    ssl_certificate     /etc/nginx/ssl/your-domain.com/fullchain.cer;
    ssl_certificate_key /etc/nginx/ssl/your-domain.com/your-domain.com.key;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    # 请求体大小限制（客户端可能上传较长的同步数据）
    client_max_body_size 2m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 超时设置
        proxy_connect_timeout 10s;
        proxy_read_timeout 30s;
        proxy_send_timeout 30s;
    }

    # 健康检查不需要记录访问日志
    location /api/health {
        access_log off;
        proxy_pass http://127.0.0.1:8080;
    }
}
```

启用站点：

```bash
sudo ln -s /etc/nginx/sites-available/worktime /etc/nginx/sites-enabled/
sudo nginx -t          # 测试配置
sudo systemctl reload nginx   # 重载 Nginx
```

### 4.2 使用 acme.sh 免费 SSL 证书

```bash
# 安装 acme.sh
curl https://get.acme.sh | sh

# 申请证书（DNS 方式支持泛域名）
~/.acme.sh/acme.sh --issue -d your-domain.com --nginx

# 安装证书到 Nginx 目录
~/.acme.sh/acme.sh --install-cert -d your-domain.com \
  --key-file /etc/nginx/ssl/your-domain.com/your-domain.com.key \
  --fullchain-file /etc/nginx/ssl/your-domain.com/fullchain.cer \
  --reloadcmd "systemctl reload nginx"
```

### 4.3 使用 Caddy（自动 HTTPS，更简单）

```bash
# 安装 Caddy
sudo apt install debian-keyring debian-archive-keyring
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update && sudo apt install caddy
```

`/etc/caddy/Caddyfile`：

```caddyfile
your-domain.com {
    reverse_proxy 127.0.0.1:8080

    # Caddy 自动申请和续签 Let's Encrypt 证书
    # 无需手动配置 SSL
}
```

```bash
sudo systemctl reload caddy
```

```bash

sudo apt install sqlite3

# 连接到数据库

# 常用查询

# 导出为 SQL
.output backup.sql
.dump
.exit
```

## 7. CI/CD 集成

### 7.1 GitHub Actions 自动部署

`.github/workflows/deploy-server.yml`（在 `worktime_server` 仓库中）：

```yaml
name: Deploy Server

on:
  push:
    branches: [main]
    paths:
      - 'lib/**'
      - 'bin/**'
      - 'pubspec.yaml'
      - 'Dockerfile'

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Build Docker image
        run: docker build -t worktime-server:latest .

      - name: Push to registry
        run: |
          docker tag worktime-server:latest registry.example.com/worktime-server:${{ github.sha }}
          docker push registry.example.com/worktime-server:${{ github.sha }}

      - name: Deploy via SSH
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SERVER_SSH_KEY }}
          script: |
            cd /opt/worktime
            docker-compose pull
            docker-compose up -d --force-recreate
            docker image prune -f
```

### 7.2 配合前端 GitHub Pages 部署

当前的 `worktime_app/.github/workflows/deploy-pages.yml` 中，前端部署到 GitHub Pages 时默认的 `API_URL` 是 `http://localhost:8080`。要使生产环境的前端指向你的后端服务器，需修改构建命令：

```yaml
# 在 flutter build web 命令中添加 --dart-define
- run: flutter build web \
    --base-href="/${{ github.event.repository.name }}/" \
    --no-source-maps \
    --dart-define=API_URL=https://your-domain.com
```

## 8. 安全注意事项

### 8.1 必须做的

- [ ] **修改 `JWT_SECRET`** — 不要使用默认值 `change-me-in-production`
- [ ] **设置 `ALLOWED_ORIGIN`** — 限制为你的前端域名，不使用 `*`
- [ ] **使用 HTTPS** — 通过 Nginx/Caddy 终止 SSL，不要让明文 HTTP 暴露
- [ ] **限制数据库访问** — 数据库文件不要放在 web 可访问的目录
- [ ] **使用独立系统用户** — 用 `worktime` 专用用户运行服务，不直接用 root

### 8.2 建议做的

- [ ] **配置防火墙** — 只开放 80/443 端口，8080 内部端口不对外开放
- [ ] **定期备份数据库** — 通过 cron 定时备份到异地
- [ ] **Docker 镜像安全扫描** — 使用 `trivy` 或 `snyk` 扫描镜像漏洞
- [ ] **日志轮转** — 配置 `logrotate` 防止日志占满磁盘

### 8.3 服务器端口开放建议

| 端口 | 协议 | 开放范围 | 说明 |
|------|------|----------|------|
| 80 | TCP | 0.0.0.0/0 | HTTP 重定向（仅 Nginx） |
| 443 | TCP | 0.0.0.0/0 | HTTPS（仅 Nginx） |
| 8080 | TCP | 127.0.0.1 | 后端服务（仅本机访问，不对外开放） |
| 22 | TCP | 你的 IP | SSH 管理（建议使用密钥认证） |

### 8.4 使用 ufw 配置防火墙

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow from your-ip to any port 22
sudo ufw enable
sudo ufw status verbose
```

## 10. 常见问题

### Q: SQLite 并发访问会不会有问题？

SQLite 适用于中低并发场景。Worktime Server 的同步模型决定了同一用户不会频繁并发写入。如果用户量较大（> 1000 活跃用户），建议迁移到 PostgreSQL。

### Q: Docker 部署时数据库数据会丢失吗？

使用卷挂载（`-v /data/worktime/data:/app/data`）并设置 `DB_PATH=data/data.db` 后，容器删除重建不会丢失数据。

### Q: 如何更新服务器版本？

Docker 部署：

```bash
docker pull worktime-server:latest   # 或重新 build
docker stop worktime-server
docker rm worktime-server
docker run ...  # 用相同的挂载卷和配置重新启动
```

原生部署：

```bash
sudo systemctl stop worktime-server
cp worktime-server worktime-server.bak   # 备份旧版本
# 上传新版本并覆盖
sudo systemctl start worktime-server
```

### Q: 如何修改 JWT 密钥？

**注意**：修改 JWT 密钥将使所有已签发的 Token 失效，所有用户需要重新登录。

```bash
# 1. 修改 .env 中的 JWT_SECRET
# 2. 重启服务
sudo systemctl restart worktime-server
```
